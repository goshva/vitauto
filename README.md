## 📌 Назначение

**v8unpack** — это консольная утилита для сборки и распаковки бинарных файлов 1С:Предприятие 8.x (`.cf`, `.cfe`, `.epf`) **без использования технологической платформы 1С**.

Основные сценарии использования:
- Распаковка расширений конфигураций (`.cfe`) в человекочитаемый вид для контроля версий
- Сборка обратно в бинарный файл после внесения изменений
- Автоматическая сборка продуктов 1С для различных платформ из одних исходников

## 🚀 Работа с файлом АРМЗакупокИПродаж__release.cfe

### 1. Распаковка .cfe в исходники

**Из командной строки:**
```bash
v8unpack.exe -E путь/к/АРМЗакупокИПродаж__release.cfe путь/к/папке/для/распаковки
```

**Пример:**
```bash
v8unpack.exe -E ./АРМЗакупокИПродаж__release.cfe ./src
```

**Из Python:**
```python
import v8unpack
v8unpack.extract('./АРМЗакупокИПродаж__release.cfe', './src')
```



После распаковки вы получите структуру папок и файлов, максимально приближенную к структуре метаданных 1С, с человекочитаемыми именами:
- Программный код хранится в отдельных файлах
- Двоичные данные макетов и картинки — в исходном виде
- Файлы хранятся в формате JSON

### 2. Сборка обратно в .cfe

После внесения изменений в исходники:

**Из командной строки:**
```bash
v8unpack.exe -B путь/к/папке/с/исходниками путь/к/новому/файлу.cfe
```

**Пример:**
```bash
v8unpack.exe -B ./src ./АРМЗакупокИПродаж__new.cfe
```

**Из Python:**
```python
import v8unpack
v8unpack.build('./src', './АРМЗакупокИПродаж__new.cfe')
```

## 🛠️ Дополнительные параметры

| Параметр | Описание |
|----------|----------|
| `--temp` | Путь до временной папки. Если указан, временные файлы не удаляются после завершения |
| `--index` | Путь до JSON-файла со словарём копирования |
| `--descent` | Включает режим наследования. Формат: `3.0.75.100` (не более 3 знаков на разряд) |
| `--auto_include` | Если указан — содержимое метаданных собирается динамически в зависимости от наличия файлов |
| `version` | Для внешних обработок: `801`, `802`, `803` (платформа)<br>Для расширений: формат `XYYZZ` (например, `80306` = 8.3.6) |

### Пример с параметрами

```bash
v8unpack.exe -E ./АРМЗакупокИПродаж__release.cfe ./src --temp ./temp --version 80306
```

## 📂 Структура распакованных файлов

После распаковки вы получите структуру, организованную по типам метаданных:

```
src/
├── MetadataObject/          # Объекты метаданных
│   ├── Catalog/             # Справочники
│   ├── Document/            # Документы
│   ├── InformationRegister/ # Регистры сведений
│   └── ...
├── CommonModule/            # Общие модули
├── Form/                    # Формы
├── Report/                  # Отчёты
└── ...
```

Код модулей всегда хранится в отдельных файлах и может быть разделён на несколько файлов.

## 🔄 Переиспользование кода

### Include-области

Для вынесения повторяющегося кода в отдельные файлы используйте области с ключевым словом `include`:

```bsl
//v8unpack #Область include_core_form3_test
ПримерКода = 1;
//v8unpack #КонецОбласти
```

При разборке код внутри области вырезается и сохраняется в отдельный файл, при сборке — вставляется обратно.

### Различие include / includr

- `include` — при разборке обновляет исходник (редактируемый)
- `includr` — при разборке **не обновляет** исходник (только для чтения)

### Динамические директивы

Позволяет добавлять директивы компилятора (например, `&НаКлиенте`) при сборке:

```bsl
//DynamicDirective
Функция HelloWorld()
КонецФункции
```

При сборке `//DynamicDirective` заменяется на указанную директиву.

## 📦 Пакетная сборка

Для сборки нескольких продуктов из одного репозитория используйте JSON-файл конфигурации:

```json
{
    "saby_vo3_83_uf": {
        "src": "src",
        "bin": "bin/saby_vo3_83_uf.epf",
        "temp": "temp",
        "index": "index.json",
        "disable": false,
        "options": {
            "descent": null,
            "auto_include": true
        }
    }
}
```

Запуск:
```bash
v8unpack.exe -EA product.json --index saby_vo3_83_uf   # распаковка
v8unpack.exe -BA product.json --index saby_vo3_83_uf   # сборка
```

## 🧪 Для разработчиков: добавление новых типов метаданных

Если утилита не распознаёт какой-то тип объектов:

1. **Найти UUID типа** — он будет в тексте ошибки
2. **Открыть файл ошибки** — в нём будет название типа метаданных
3. **Найти английское название** в Синтакс-помощнике 1С (например, `MetadataObject:InformationRegister.Forms`)
4. **Добавить класс** в папку `MetadataObject/`
